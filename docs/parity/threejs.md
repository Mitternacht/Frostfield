# Three.js parity checklist

This checklist compares Frostfield with **Three.js r187** (released 2026-10-30). It starts with the
recovered Frostfield inventory at `157bb26` and covers the integration through `0d83e34`
(2026-11-11). Third-party package versions were checked on 2026-11-09.

Each area compares three tiers separately:

- **Core**: the `three` package.
- **Addons**: the official modules in `examples/jsm`.
- **Third-party**: the wider ecosystem, such as pmndrs, three-mesh-bvh, three-gpu-pathtracer and glTF-Transform.

Browser delivery features, such as WebXR sessions, DOM overlays, canvas management and web GUIs, are a platform
difference rather than a parity gap. They appear once, in [Platform differences](#platform-differences), with
their native Apple equivalent.

| Status | Meaning |
| --- | --- |
| ✅ Implemented | A public API exists, backed by a test or an evidence page. |
| 🟡 Partial | It exists, with the gaps stated in the row. |
| ❌ Missing | There is no public Frostfield API. Lab-only code counts as missing. |
| 🌐 Platform difference | A native Apple facility covers it. Not counted in the summary. |

> [!NOTE]
> A performance comparison needs the same hardware, scene, resolution and quality settings on both sides.
> The integrated package at `0d83e34` ran 2,183 tests in 426 suites on an M4 Max, passing with the optional
> benchmark and capture tests skipped, and a second run of 6 tests in 2 suites passed. The iPad Pro (M5) and
> Vision Pro simulators each passed a focused run of 345 tests in 46 suites. The Lab built for all three
> destinations in Xcode 27.2. The three Asset Studio captures reproduced the previous checkpoint's images byte
> for byte. [Capture evidence](../evidence/asset-studio.md) Tests and captures used Metal API Validation. The
> Xcode bridge timed out resolving the package destination, so verification used `xcodebuild` with internal
> DerivedData. Physical iPhone, iPad and Vision Pro qualification and matched Three.js benchmarks remain open.

The **Frostfield API** column names the public Swift declarations in the integrated tree, or — when there is none.
Rows say whether a feature works in the raster renderer, the path tracer, or both.

## Method and limits

- Three.js capabilities come from the r187 source tree, the official addons and current third-party releases.
- Frostfield statuses start from the `157bb26` source, tests and evidence review. The follow-up review
