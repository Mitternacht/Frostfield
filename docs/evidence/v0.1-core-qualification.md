## Gate 2: clean consumer

**Partly met. Not checked.** A package consumer resolved Frostfield alone at the
candidate revision, loaded the packaged shaders, and rendered on the Mac GPU and the
iOS Simulator. The gate's remaining parts are open: the consumer is a package with
tests, not an app that runs the UIKit example, and it resolved from a local `file://`
git URL, not a hosted URL or tag.

Procedure. A scratch directory outside the repository held a new Swift package
(`FrostfieldConsumer`, tools 6.2, Swift 6 language mode, iOS 26 and macOS 26) whose only
dependency is:

```swift
.package(url: "file://<path to a Frostfield clone>", revision: "d91cc16528dc5a3067e5f83eec56a0e73ebdbfc0")
```

Its library target builds a scene from public API only: `MeshRenderer`, the cube mesh,
the built-in unlit material, and `consumer_tint_fragment`, a fragment function in the
consumer's own `Shaders/*.metal`, declared from [materials](../materials.md) without
Frostfield's header and loaded with `makeDefaultLibrary(bundle: .module)`. A small
workspace beside it has a shared scheme whose test action sets `MTL_DEBUG_LAYER=1`. The
workspace was opened in the Xcode MCP bridge as its own workspace.

Results:

- Resolution: one pin, `frostfield`, kind `localSourceControl`, revision `d91cc16`. Xcode
  cloned it into the consumer's own `SourcePackages/checkouts`, whose `HEAD` was
  `d91cc16` with a clean working tree, and compiled `Mesh.metal`, `Triangle.metal`, and
  `Unlit.metal` from that checkout. No sibling repository, local package path, or
  GlassWeave was involved.
- `RunAllTests` on My Mac and on the iPhone 17 simulator: 5/5 each. `Frostfield's
  packaged shaders load and draw the unlit material` (the centre pixel's bytes equal
  (0.25, 0.5, 0.75, 1) in 8-bit unorm), `The consumer's own material shades Frostfield's
  mesh` (equal to (1, 0.5, 0, 1)), `Parameter updates create no pipelines` (30 colors, each read back,
  counters unchanged at 3 pipelines), `A missing function lists the consumer's fragment
  functions`, and `Metal API validation wraps the device` (the debug-layer device on
  both destinations).

Error and lifecycle behavior a consumer gets, each with its own evidence: construction
fails with `RendererError` (missing device, library, function, queue, pipeline, buffer,
depth state); invalid camera values with `ProjectionError`; invalid geometry with
`GeometryError`; invalid material functions and parameters with `MaterialError`; a
target in the wrong color format, a missing depth attachment, and a mesh or material
from another device or renderer stop on a precondition before encoding; a frame with no
free slot or no target is skipped and reported, never waited for. (At `d91cc16` a
multisample color attachment, a depth attachment for the triangle renderer, and a stencil
attachment were not checked and reached Metal; the review fixes below add those checks.) Hosts pause hidden and
background scenes through `RenderSchedule` ([Checkpoint A](checkpoint-a-host.md)).

## Mac characterization (not device evidence)

Measured on the Apple M5 Mac only. It says nothing about iPhone or iPad cost.

Procedure: an executable in the scratch consumer, built Release and launched through
Xcode MCP `RunProject` with Metal API validation off (the device type was
`AGXG17GDevice`, not the debug layer). Off-screen 1206 × 2622 `bgra8Unorm` color target
with a `depth32Float` attachment, the cube, a new transform and new material parameters
every frame, alternating the unlit and consumer materials. Paced: each frame waited for
the previous one's completion report, so no frame was skipped. Three launches, each with
three rounds of 1,000 frames.

| Measurement | Result |
| --- | --- |
| `drawFrame` CPU time, p50 per round | 8.1–11.3 µs |
| `drawFrame` CPU time, p95 / p99 per round | 8.8–36.3 µs / 12.2–73.0 µs |
| Submit-to-completion-report latency, p50 per round | 249–357 µs (includes queue scheduling and the completion callback; not GPU duration) |
| Resource counters across 3 × 3,000 frames | Unchanged: 5 pipelines, 1 depth state, 5 buffers, 1,040 bytes; 0 failed, 0 skipped |
| Making a material again for a prepared function (cache hit) | 0.46–0.67 µs, no pipeline created |
| The same function from a new library object | 32–122 µs, one pipeline created |
| A function compiled from source in that launch | 77–114 µs for its pipeline |

The pipeline-creation times are warm: Metal keeps its own shader caches across launches.
The first launch of the tool (with API validation on) took 181 ms to set up the scene,
the first launch without validation 41 ms, and later launches 2–6 ms. A cold first-launch cost on a device is unmeasured. Because
`makeDefaultLibrary` returns a new library object on every call, an app should keep the
library it makes materials from; [materials](../materials.md) documents the cache key.

## Review fixes after this record (2026-11-09)

An independent review of the candidate found defects that are now fixed on the branch
(see [the task list](../../tasks/todo.md) for each task's evidence). None changes a gate's
status above.

- Resource-reuse evidence: the renderers' `ResourceStatistics` are their own report,
  kept where they create objects, and `TriangleRenderer`'s are constant by
  construction. The package tests now also run the renderers on a test device wrapper
  that logs every object-creating call, and require that drawing logs none; deliberate
  per-frame buffer and pipeline creation in `drawFrame` failed them. The consumer's
  `Parameter updates create no pipelines` and the Mac characterization above used the
  renderer's own counters only.
- Targets: multisample color, a depth attachment for the triangle renderer, and stencil
  attachments now stop on a precondition before a command buffer exists.
- Scheduling: a requested frame that found no drawable while nothing was in flight could
  stall; it is now retried once, then waits for an invalidation.
- API validation: the validation check fails, rather than skips, when
  `FROSTFIELD_REQUIRE_API_VALIDATION=1` (shared schemes and CI) and validation is missing.
- The lab's status label exposes its `key=value` counters only to UI tests; VoiceOver
  reads the visible text.

After the fixes: package 116 test functions, 208 cases, all passed with Metal API
validation on My Mac; FrostfieldLab UI tests 13/13 on the iPhone 17 simulator. The
clean-consumer run was not repeated after the fixes.
