## FF-08 — Supply a custom material shader

Create the first material binding contract from a working built-in unlit material and a caller-supplied shader fixture.

**Acceptance criteria**
- [x] An app supplies a shader function and documented parameters to shade the existing mesh.
- [x] Missing functions or incompatible bindings produce actionable errors; parameter updates reuse prepared pipelines.
- [x] The custom and built-in material paths use the same rendering/lifetime rules without requiring a material graph.

**Evidence (2026-11-09):** [materials and the binding contract](../docs/materials.md). A `Material<Parameters>` is a fragment function plus a parameter value. `MeshRenderer.makeUnlitMaterial(color:)` makes the built-in unlit material (`Shaders/Unlit.metal`, `ff_unlit_fragment`, parameters `UnlitParameters` = the shared C record `FFUnlitParameters`), and `makeMaterial(fragmentFunction:library:parameters:)` takes a fragment function from any library the app makes with the renderer's device. The contract: the function reads the varyings `[[position]]`, `float3 [[user(ff_model_normal)]]`, and `float3 [[user(ff_model_position)]]` (Metal matches them to `ff_mesh_vertex`'s output by user name, so an app declares its own struct without Frostfield's header) and one read-only parameter block at fragment `[[buffer(0)]]` whose size equals `MemoryLayout<Parameters>.size` and is under 4096 bytes. Making a material checks, before any frame uses it: the library's device, a missing function (the error lists the library's fragment functions), a non-fragment function (rejected before Metal sees it, because Metal API validation aborts on one), Metal's pipeline error (for example a varying the vertex stage does not write), and, through `MTLRenderPipelineReflection` binding info, any texture, sampler, extra or writable buffer, and the parameter-block size against the Swift type; each `MaterialError` description names the function and the fix. `MaterialPipelineCache` (internal, `PipelineCache.swift`) creates one pipeline per library object and function name and reuses it for later materials. `drawFrame(mesh:material:transform:camera:target:)` copies the parameters into the frame's commands with `setFragmentBytes`, so drawing creates nothing and a parameter change never reaches a frame already submitted. `drawFrame(mesh:transform:camera:target:)` now draws the built-in normal diagnostic through the same material path. Xcode MCP `RunAllTests`, scheme `Frostfield (Frostfield Workspace)`, My Mac (Apple M5, macOS 27.2), `MTL_DEBUG_LAYER=1` (`API validation wraps the device when requested` passed): 109 test functions, 200 cases, all passed.
